# 영적기록ON

꿈·환상·예언·감동과 기도 중 받은 내용을 **말로 남기면**, 글로 옮기고 정리·분류해
보관하고, 원하는 것만 골라 워드프레스 초안으로 보내는 PWA.

> **말한다 → 정리된다 → 분류된다 → 보관하거나 블로그에 올린다.**

## 지금 되는 것

| 기획서 | 상태 |
|---|---|
| §3 녹음 → 글 변환 | ✅ 브라우저 음성 인식(`SpeechRecognition`). 없으면 녹음만 남고 나중에 직접 옮긴다 |
| §4 한 녹음 안의 여러 기록 나누기 | ✅ 녹음 중 「새 기록으로 나누기」 + 말투로 짐작한 자리 추천 |
| §5 정리문·요약·제목 | ✅ **규칙 기반** — 군더더기를 덜어내고 문장을 고를 뿐, 새 문장을 짓지 않는다 |
| §6 자동 분류(인물·장소·주제·감정·말씀·상징) | ✅ 추천만 하고 확정은 사용자가 한다 |
| §7 받은 내용 / 해석 / 관련 사건 분리 | ✅ 덮어쓰지 않고 날짜순으로 쌓인다 |
| §9 홈·녹음·정리 확인·보관함·상세·발행 | ✅ 여섯 화면 |
| §10 워드프레스 초안 전송 | ✅ 서버 라우트(`/api/publish`) — 기본 `draft`, 예약·공개도 가능 |
| §11 블로그 글 구조 | ✅ 절 단위로 빼기 선택 + 실명 가리기(조사까지 고침) |
| §12 비공개·백업 | ✅ 표는 본인만, 음성 통은 비공개(서명 주소), 전체 백업 내려받기 |
| §14 PWA | ✅ manifest + 서비스워커(기록은 캐시하지 않는다) |

**아직 없는 것**: Blog ON 직접 연동(지금은 마크다운 복사), 배우자·초대 공유의
실제 공유 기능(값은 저장되지만 남에게 열리지 않는다), 반복 패턴 분석, 전자책.

## 왜 언어모델을 부르지 않는가

이 앱이 다루는 글에는 배우자·자녀의 실명, 교회의 사정, 어떤 사람을 향해 받았다고
인식한 메시지가 그대로 적힌다. 「모든 기록은 기본 비공개」(§12)라고 적어 놓고 그
원문을 정리해 달라며 통째로 밖으로 보내는 것은 앞뒤가 맞지 않는다.

그리고 §8 이 요구하는 것은 똑똑함이 아니라 **절제**다 — 말하지 않은 장면·사람·
말씀을 보태지 않을 것. 규칙은 모델보다 덜 똑똑하지만 **없는 말을 지어내지 못한다.**
이 일에서는 그 성질이 더 중요하다.

나중에 모델을 붙이고 싶어지면 `src/lib/organize.ts` 의 `organize()` 하나만 갈아
끼우면 된다. 화면은 그 반환 모양만 본다.

## 시작하기

```bash
npm install
cp .env.example .env.local     # 값을 채운다
npm run dev                    # http://localhost:3000
```

Supabase SQL 편집기에서 `supabase/migrations/0001_spirit_log.sql` 을 한 번 실행한다.
**실행 전에는 화면이 열려도 아무것도 저장되지 않는다(표가 없다).**

### 환경 변수

| 이름 | 어디서 쓰나 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 브라우저. 표의 정책이 본인 것만 열어 준다 |
| `WORDPRESS_URL` / `WORDPRESS_USER` / `WORDPRESS_APP_PASSWORD` | **서버만.** `NEXT_PUBLIC_` 을 붙이면 안 된다 |

애플리케이션 비밀번호는 워드프레스 관리자 → 사용자 → 프로필에서 발급한다.
로그인 비밀번호가 아니다.

## 검사

```bash
npm run typecheck   # tsc --noEmit
npm run check       # 순수 함수 64가지 대조 (scripts/check-organize.mjs)
npm run build
```

`npm run check` 가 보는 것: 나누기·군더더기 덜어내기·요약이 **원문에 있는 말만**
쓰는지, 종류 추천이 확정이 아닌지, 성경 구절·인물·장소를 찾는지, 실명을 바꿀 때
조사가 따라 바뀌는지(「교회 지인를」이 아니라 「교회 지인을」), 블로그 절이 §11
차례대로 서는지.

## 이 폴더를 제 레포로 떼어내기

지금은 `bible-app` 리포 안에 있다(이 세션에 새 레포를 만들 권한이 없었다).
독립 레포로 옮기려면 GitHub 에서 빈 레포를 하나 만든 뒤:

```bash
cd spiritual-log-on
git init && git add -A && git commit -m "영적기록ON 첫 판"
git remote add origin https://github.com/<사용자>/spiritual-log-on.git
git push -u origin main
```

Vercel 에 올릴 때는 Root Directory 를 이 폴더로 잡거나, 위처럼 떼어낸 레포를
그대로 연결하면 된다. 환경 변수 넷은 Vercel 쪽에도 넣어야 한다.

## 사람이 봐 줘야 하는 것

1. `supabase/migrations/0001_spirit_log.sql` 실행
2. 진짜 로그인 상태의 왕복 — 녹음 → 정리 → 저장 → 해석 추가 → 워드프레스 초안
3. 실제 폰 크롬에서 **한국어 받아쓰기가 쓸 만한지** (사파리에는 없다. 녹음은 된다)
4. 긴 녹음(10분 이상) 업로드
5. 워드프레스 애플리케이션 비밀번호로 초안이 실제로 꽂히는지
