# 카드가계부

카톡·문자로 오는 **삼성카드 결제 알림을 읽어 가계부로 정리하는 앱**.
데이빗바이블과는 별개의 Expo 앱이다(물품관리ON 과 같은 방식으로 떼어 놓았다).

> 이름 「카드가계부」는 자리를 잡아 둔 것이다. 바꾸려면 `app.json` 의
> `name`·`slug`·`scheme`·`package`/`bundleIdentifier` 를 같이 고친다.

---

## 먼저 알아야 할 것 — 카톡은 대화를 읽게 해 주지 않는다

카카오는 대화 내용을 읽는 권한을 바깥 앱에 열지 않는다. **공식 API 가 없다.**
그래서 문자를 앱 안으로 들이는 길은 셋뿐이고, 셋 다 만들어 두었다.

| | 길 | 되는 곳 | 지금 상태 |
|---|---|---|---|
| ① | **붙여넣기** — 카톡에서 복사 → 앱에 붙여넣기 | 웹·앱 모두 | **다 됨. 브라우저에서 왕복 확인** |
| ② | **공유하기** — 카톡 메시지 길게 눌러 「공유 → 카드가계부」 | 안드로이드 앱 | 코드는 다 썼다. **APK 를 구워야 돌아간다** |
| ③ | **알림 가로채기** — 카드 문자가 오면 그 자리에서 자동으로 담김 | 안드로이드 앱 | 코드는 다 썼다. **APK 를 구워야 돌아간다** |

**아이폰과 웹에서는 ①뿐이다.** iOS 는 다른 앱의 알림을 읽는 길 자체가 없다.
그래서 ②③ 은 **덤으로** 지었다 — 없어도 앱은 ① 만으로 온전히 돌아가고,
네이티브 모듈이 없는 곳에서는 `src/lib/capture.ts` 가 조용히 물러선다.

## 이 앱이 정보를 다루는 방식

**카드 내역을 서버로 보내지 않는다.** 결제 이력은 언제 어디서 무엇을 했는지가
통째로 드러나는 기록이다. 그래서 로그인도 Supabase 도 없고, 담긴 것은 전부
기기 안(AsyncStorage)에만 있다. 기기를 바꿀 때는 설정의 CSV 내보내기로 옮긴다.

알림 가로채기(③)는 기기의 모든 알림을 볼 수 있는 자리에 서기 때문에 문을 좁게
깎았다 — 정해 둔 앱(카톡·문자)의 알림만 보고, 그중에서도 「승인/취소」와 금액이
같이 있는 것만 담고, 나머지는 읽는 즉시 버린다(`CardNotificationListener.kt`).

## 설계에서 눈여겨볼 곳

- **`src/lib/cardMessage.ts` 가 이 앱의 심장이다.** 수집 경로가 ①②③ 무엇이든
  앱에 들어오는 것은 결국 같은 문자열이라, 읽는 일만 순수 함수로 떼어 놓았다.
  화면을 못 띄우는 곳에서도 검사가 된다.
  - 구분자를 믿지 않는다. 대신 **「한 통이 다 찼는가」**(금액·날짜·가맹점)로
    자른다 — 카톡 대화를 통째로 붙여넣어 잡담이 섞여도 그 잡담이 가맹점 자리로
    딸려 들어가지 않는다.
  - **가맹점은 「몇 번째 줄」로 찾지 않는다.** 카드사·이름·금액·날짜·할부·누적
    처럼 정해진 조각을 다 지우고 남는 글자를 가맹점으로 본다. 줄 나눔이 카드사
    마다 다르고 한 줄로 이어 붙어 오는 문자도 있기 때문이다.
  - 문자는 `09/21` 까지만 준다. **연도는 우리가 정한다** — 오늘을 기준으로 잡되
    미래로 넘어가면 지난해로 돌린다. 1월에 받은 12월 문자가 올해 12월로 적히면
    그 한 건이 한 해 내내 앞날에 떠 있게 된다.
- **같은 문자를 두 번 붙여넣어도 두 번 담기지 않는다**(`txnKey`). 이 일은 반드시
  일어나고, 그때 한 달 치가 두 배로 불어나면 이 앱은 쓸모가 없다.
- **취소는 빼기다**(`summarize`). 승인만 더하면 결제 취소한 53,000원이 쓴 돈으로
  남는다.
- **갈래를 고치면 가맹점 단위로 기억한다**(`setOverride`). 규칙보다 사람이 고친
  것이 언제나 먼저다 — 기계가 다음 날 다시 뒤집으면 고칠 마음이 사라진다.
- 해외 승인은 원화 금액이 문자에 없다. **0원으로 두고 합계에서 빼되, 화면에
  「금액을 못 읽은 건이 있다」고 적는다.** 0을 조용히 더하면 그 달 합계가 틀린다.

## 돌려 보기

```bash
npm install
npm run web          # 웹 (붙여넣기까지 전부 됨)
npm run typecheck
```

안드로이드 앱(②③ 을 쓰려면):

```bash
npm run build:android   # eas build --platform android --profile preview
```

> **EAS 무료 플랜 빌드 수를 쓴다.** 데이빗바이블 쪽 기록을 보면 이 계정은
> 한 달 빌드 수가 정해져 있으니, 굽기 전에 남은 수를 확인할 것.

## 아직 사람이 봐 줘야 하는 것

1. **진짜 삼성카드 문자 몇 통**을 붙여넣어 제대로 읽히는지. 파서는 흔한 형식
   다섯 가지로 맞춰 두었는데, 실제로 오는 문구가 조금씩 다르면
   `src/lib/cardMessage.ts` 의 조각 규칙을 더해야 한다. **못 읽은 문자는 화면에
   그대로 보여 주니** 그 글을 그대로 옮겨 주면 된다.
2. **②③ 은 APK 를 한 번 구워야 확인된다.** 이 세션에서는 안드로이드 빌드를
   돌릴 수 없어 코틀린 코드를 **컴파일해 보지 못했다.** 첫 빌드에서 오류가 나면
   `modules/card-capture/android/` 가 볼 곳이다.
3. ③ 을 켠 뒤: 카톡 **알림 미리보기를 「내용 숨김」으로 해 두면 읽을 글이 없다.**
   그 설정을 켜 두었다면 ③ 대신 ②(공유하기)를 쓴다.
4. 갈래 규칙(`src/lib/category.ts`)이 본인 씀씀이에 맞는지. 틀린 것은 앱에서
   고치면 그 가맹점은 다음부터 기억한다.

## 이 세션에서 확인한 것 (2026-09-21)

- `tsc --noEmit` 오류 0, `expo export -p web` 성공(화면 다섯 전부 정적 생성).
- 파서를 노드로 돌려 12가지 입력을 눈으로 대조 — 표준 승인·카드 뒷자리·할부·
  취소·해외승인·여러 통 이어붙임·구분자 없이 이어붙임·카톡 내보내기(안드로이드/
  아이폰)·연도 넘어감·잡담 섞임·금액 없는 안내문. 전부 예상대로.
  분류 18건도 대조 — 쿠팡이츠(식비)와 쿠팡(온라인쇼핑)이 갈리는지 포함.
- **실제 브라우저(Chromium)에서 왕복을 돌렸다**: 문자 5통 붙여넣기 → 미리보기 →
  담기 → 홈 합계(456,900원) → 내역 → 편집 시트 → 흐름 → 설정. 콘솔 에러 0
  (favicon 404 하나뿐).
- **같은 문자를 두 번 붙여넣어** 두 번째에 「이미 담긴 2건은 뺐습니다 / 0건 담기」가
  뜨는 것까지 확인.
- 어두운 모드 확인. 프리렌더된 밝은 화면이 그대로 굳는 것을 찾아
  `use-color-scheme.web.ts` 로 고쳤고, 내용 아래가 순검정으로 남는 것은
  `+html.tsx` 로 고쳤다.
