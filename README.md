# 물품관리ON (Inventory ON)

> 교회와 가정의 모든 물품을 **사진으로 보고**, 어디에 무엇이 몇 개 있는지 빠르게 찾는 수납 지도

- 앱: Expo (React Native) — 웹 + 안드로이드/iOS 한 벌
- 서버: Supabase (Postgres + Auth + RLS + Storage)
- 계정: **데이빗바이블·교회운영ON 과 같은 Supabase 프로젝트**를 쓴다. 쓰던 이메일로 그대로 들어온다.

## 지금 되는 것 (1단계)

- 관리 공간(교회·가정·그 밖)을 나누어 관리 — 교회 물품과 집 물품은 섞이지 않는다
- `건물 → 층 → 방 → 수납 위치` 계층, **공간 사진 위에 번호 핀**
- 사진·이름·위치·수량만으로 30초 등록, 구입 정보는 나중에 보완
- 수량 ±, 최소 수량 이하면 부족·품절 표시
- 위치 이동(일부 수량만 떼어 옮기기 포함), 모든 변경의 이력
- 처분(사용 완료·폐기·분실·기증·매각)과 30일 휴지통·복원
- 물어보듯 찾기 — 「마이크 어디 있지?」, 「주방 종이컵 몇 개?」
- 구성원 권한 5단계(대표 관리자 / 공간 관리자 / 담당자 / 일반 / 열람)

## 아직 안 한 것 (2·3단계)

QR·바코드, 대여·반납, 푸시 알림, 영수증 OCR·AI 사진 인식, 월간 보고서·엑셀/PDF
내보내기, 구입 요청·승인 흐름, 오프라인 임시 저장.

## 빠른 시작

```bash
npm install
cp .env.example .env     # Supabase URL / anon key
npm run web
```

자세한 것은 [`DEV-SETUP.md`](./DEV-SETUP.md), 교회운영ON 에 붙이는 법은
[`docs/교회운영ON-연동.md`](./docs/교회운영ON-연동.md).

## 설계에서 물러서지 않은 것

- **사진 통은 비공개다.** 남의 집 안방과 교회 사무실 내부가 찍힌다. 주소가 한 번
  새면 되돌릴 길이 없어, 화면은 볼 때마다 한 시간짜리 서명 주소를 받아 쓴다.
- **수량은 서버 함수로만 바꾼다.** 수량 칸과 이력을 따로 부르면 사이에서 끊길 때
  과거 수량을 되짚을 수 없다.
- **지우지 않는다.** 다 쓴 소모품은 상태만 바뀌고, 삭제는 30일 휴지통이 있는
  소프트 삭제다. 구입·사용 기록이 다음 구입의 근거다.
- **찾기에 언어모델을 부르지 않는다.** 물건 이름 몇 개 찾자고 집 안 물건 목록을
  밖으로 보낼 이유가 없다. 묻는 말투와 조사를 떼는 규칙으로 갈음했다.
