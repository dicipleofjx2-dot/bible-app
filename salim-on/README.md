# 살림ON

집안일을 **분류하고 · 담당자를 배치하고 · 시간을 배치하고 · 확인하고 · 점수를 매기는**
가정용 앱. Expo(React Native) + Supabase.

데이빗바이블(`../`)과 **같은 Supabase 프로젝트**를 쓰지만 **별도 앱**이다 —
데이빗바이블은 개인 경건훈련 앱이고 살림은 경건훈련이 아니다. 물품관리ON 을
밖으로 내보낸 것과 같은 판단이다. 계정은 공유되므로 쓰던 이메일로 그대로 들어온다.

## 시작하기

```bash
cp .env.example .env     # Supabase URL/anon key 를 채운다
npm install
npm run web              # http://localhost:8081
npm run typecheck
```

**먼저 `supabase/migrations/0001_household.sql` 을 Supabase SQL 편집기에서 실행한다.**
실행 전에는 화면이 열려도 아무것도 저장되지 않는다(표가 없다).

## 화면

| 경로 | 하는 일 |
|---|---|
| `/` | **오늘** — 오늘 치를 시간순으로, 내 일감을 맨 위로. 체크는 여기서 한다 |
| `/chores` · `/chore/[id]` | **집안일** — 분류별 목록과 한 가지를 적는 폼 |
| `/schedule` | **배치** — 그 주를 펼치고, 공평하게 자동 배정(미리보기 → 확정) |
| `/review` | **확인함** — 끝낸 일에 별점을 매겨 승인하거나 다시 시킨다 |
| `/scores` | **점수판** — 주간·월간 순위와 뱃지 |
| `/members` | **식구** — 초대코드, 역할, 계정 없는 식구 |
| `/join` · `/sign-in` | 집 만들기·들어가기, 로그인 |

## 이 앱이 붙잡고 있는 판단들

- **점수는 표의 트리거가 매긴다**(`home_score_task`). 화면이 매기면 폰 시계를
  돌려 정시 보너스를 받는 길이 열린다. `src/lib/chores.ts` 의 점수 함수는
  화면에 미리 보여 주는 **예상 점수**일 뿐이고, 셈하는 식은 SQL 과 같다.
- **하루는 서울에서 끊는다.** UTC 자정으로 끊으면 저녁 설거지가 어제 일이 된다.
- **계정이 없어도 식구가 된다.** 아이에게 이메일을 만들게 하지 않는다. 이름만
  적어 두면 일감이 배정되고 점수가 쌓이고, 나중에 초대코드로 들어오면 **같은
  이름의 그 자리에 계정이 붙어** 점수가 이어진다.
- **식구를 뺄 때 줄을 지우지 않고 재운다**(`active=false`). 지우면 그 사람이 한
  일감의 담당자가 비어 지난 점수판이 유령이 된다.
- **공평은 「몇 개」가 아니라 「몇 점」으로 잰다.** 돌아가며 주면 한 사람이
  어려운 일만 맡는 일이 생긴다(`assignFairly`).
- **자동 배정은 미리 보여 준 뒤 확정한다.** 눌렀더니 바로 바뀌면, 한 번 잘못
  누른 사람이 다시는 안 누른다.
- **펼치기는 몇 번을 눌러도 안전하다.** `(chore_id, on_date)` 유일 제약 +
  `ignoreDuplicates` — 끝낸 표시나 바꿔 둔 담당자가 되돌아가지 않는다.
- **확인 전에는 0점이다.** 확인이 형식이 되면 확인할 이유가 없다.
- **반려에 벌점을 두지 않았다.** 다시 하는 것이 이미 대가다.
- **건너뛴 일은 맡은 적 없는 것으로 친다.** 아파서 못 한 날이 개근을 깬다면
  아무도 정직하게 「건너뜀」을 누르지 않는다.
- **뱃지에는 받은 이유를 같이 적는다.** 이유 없이 붙는 상은 다음 주에 다툴 씨앗이다.
- **남의 집 살림은 한 줄도 안 보인다.** 정책은 「이 집 식구인가」 하나뿐이고,
  들어오는 문은 초대코드 하나다(집 목록을 보여 주고 고르게 하지 않는다).
- **자기 일은 스스로 체크한다.** 아이가 자기가 한 일을 못 누르면 이 앱을 쓸
  이유가 없다. 다만 **담당자 바꾸기·별점·승인은 관리자만** 한다(표의 트리거가 막는다).

## 검증 (2026-09-21)

- `npx tsc --noEmit` 오류 0.
- `src/lib/chores.ts` 의 순수 함수를 노드로 돌려 **73가지**를 대조 — 서울 날짜
  경계, 윤년·월말, 격주가 주 단위로 세어지는지, 31일이 없는 달을 건너뛰는지,
  무거운 일을 받은 사람이 더 안 받는지, 이미 진 짐이 반영되는지, 시간이 겹치면
  다른 사람에게 가는지, 혼자일 때는 겹쳐도 맡기고 알리는지, 같은 입력이 늘 같은
  결과를 내는지, 건너뛴 일이 개근을 안 깨는지 — 전부 예상대로.
- `npx expo export -p web` 로 11개 경로가 정적 렌더링까지 통과.
- **실제 브라우저(Chromium)에서 밝은/어두운 모드로 일곱 화면을 그려 확인**했다
  (Supabase 응답을 가짜로 채워 로그인 상태를 만들었다). 콘솔 오류 0. 그 과정에서
  찾아 고친 것: ① 하위 화면을 새로고침하면 전부 `/join` 으로 튕기던 것(집을 다
  읽기 전에 리다이렉트), ② `/chore/<id>` 를 주소로 바로 열면 폼이 빈 채로 굳던
  것(자료보다 먼저 굳은 useState), ③ 어두운 모드에서 「했음」 ✓ 가 안 읽히던 것.
- 단추를 실제로 눌러 확인한 것: 집안일 만들기로 들어가기, 반복을 「매월」로
  바꾸면 요일 대신 날짜 칸이 나오는지, 난이도를 올리면 예상 점수가 따라 오르는지,
  자동 배정 미리보기가 점수 적은 사람에게 가는지.

## 사람이 봐 줘야 하는 것

1. `0001_household.sql` 실행.
2. 진짜 로그인 상태의 왕복 — 집 만들기 → 식구 넣기 → 집안일 적기 → 주 펼치기 →
   자동 배정 → 체크 → 확인 → 점수판.
3. **다른 계정으로 초대코드를 넣어**, 관리자가 이름만 적어 둔 식구 자리에 계정이
   제대로 붙는지(점수가 이어지는지).
4. 식구 계정으로 **남의 일감을 체크하려 하면 막히는지**, **스스로 승인이 안 되는지**.
5. 폰에서의 손가락 크기(체크 단추 52px, 요일 단추 44px).

## 아직 안 한 것

알림(정해진 시각에 「지금 할 차례입니다」), 사진으로 확인(청소 전후), 주간 결산
보내기, 보상 교환(점수 → 용돈·상품), 반복 예외(여행 간 주 통째로 쉬기),
분류 순서 바꾸기, 네이티브 빌드(EAS).
