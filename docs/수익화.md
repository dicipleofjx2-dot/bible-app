# 데이빗바이블 수익화 — 현재 구조와 현실적인 숫자

작성 2026-08-06. 목표로 제시된 금액은 **한 달에 1,000만원**이다. 이 문서는
그 숫자가 현재 구조에서 어떻게 나오는지(또는 왜 안 나오는지)를 계산해두고,
무엇을 바꿔야 근접하는지를 적어둔다.

## 지금 돈이 들어올 수 있는 경로

| 경로 | 단가 | 상태 |
| --- | --- | --- |
| 정기후원 (구독) | 월 5,000원 | ✅ 계좌이체 + 관리자 승인으로 동작 |
| 데이빗북스 책 판매 | 책마다 `books.price` | ✅ 계좌이체 + 관리자 승인으로 동작 |
| 쿠팡파트너스 | 구매액의 약 3% 수수료 | ✅ 링크만 있으면 동작, 코드 불필요 |
| 후원계좌 직접 입금 | 자유 | ✅ 계좌번호 노출만으로 동작 |

2026-08-06 이전까지는 위 4개 중 **아래 두 개만** 실제로 작동했다. 정기후원
버튼은 결제를 전혀 거치지 않고 구독을 켜주기만 했고(즉 수익 0원 + 유료 콘텐츠
무료 개방), 책 구매 버튼은 RLS에 막혀 항상 실패했다. `0033_manual_payment_approval.sql`
에서 고쳤다.

## 1,000만원이 되려면 몇 명이 필요한가

한 가지 경로만으로 채운다고 가정했을 때:

| 경로 | 필요 규모 (월 1,000만원) |
| --- | --- |
| 정기후원만 | **2,000명**이 매달 5,000원 |
| 1만원짜리 책만 | **1,000권** 판매 |
| 3만원짜리 교재만 | **334권** 판매 |
| 쿠팡파트너스만 | 약 **3.3억원**어치 구매 유발 (수수료 3% 가정) |

섞으면 이렇게 된다 — 예를 들어 정기후원 300명(150만원) + 3만원 교재 200권
(600만원) + 1만원 책 250권(250만원) = 1,000만원.

**정직하게 적어두면**: 한 달 안에 이 규모는 어렵다. 앱에는 아직 유료 콘텐츠가
한 건도 팔린 적이 없고(결제가 동작한 적이 없으므로), 첫 달 매출은 사실상
**교회 성도 수와 그 중 실제로 지갑을 여는 비율**이 상한이다. 성도 200명 규모에서
정기후원 전환율이 후하게 잡아 20%면 40명 × 5,000원 = 월 20만원이다.
1,000만원은 여기서 50배다.

## 그래서 무엇이 실제로 레버가 되는가

숫자를 키우는 순서대로:

1. **객단가.** 5,000원짜리 후원으로 1,000만원을 만들려면 2,000명이 필요하지만,
   3만원짜리 성경공부 교재는 334권이면 된다. 교재/저서 가격을 제대로 매기는
   것이 후원자 수를 늘리는 것보다 훨씬 빠르다. 지금 `books.price`가 0원이면
   `hasBookAccess()`가 무조건 열어주므로(의도된 동작), 팔 책은 반드시 가격을
   넣어야 한다.
2. **결제 이탈.** 계좌이체 + 수동확인은 "지금 당장 시작할 수 있다"는 게 유일한
   장점이고, 전환율은 카드결제보다 확연히 낮다. 앱을 벗어나 은행 앱을 열고,
   계좌번호를 옮겨 적고, 승인을 기다려야 한다. 규모를 키울 생각이면 포트원/토스
   연동이 필요하다 — 사업자등록과 PG 심사에 보통 1~2주.
3. **모수.** 앱이 교회 내부에만 있으면 상한이 성도 수다. 플레이스토어 정식
   출시(현재는 APK 사이드로드)와 외부 유입이 없으면 2,000명은 나오지 않는다.
4. **재구매.** 정기후원은 지금 자동결제가 아니라 **한 달짜리 수동 갱신**이다
   (`approvePayment()`가 `current_period_end`를 한 달 뒤로 잡는다). 다음 달에
   다시 입금해달라고 알려주지 않으면 그대로 빠져나간다. 만료 임박 안내가
   없다는 게 현재 가장 큰 누수 지점이다.

## 아직 안 된 것 / 다음에 할 것

- **만료 안내 없음.** 구독 만료가 다가와도 사용자에게 알리지 않는다. 재입금
  유도 화면이나 알림이 필요하다.
- **환불 처리 UI 없음.** `purchases.status`에 `refunded`가 있지만 관리자
  화면에서 환불로 바꾸는 버튼은 없다. 지금은 SQL로 직접 바꿔야 한다.
- **법적 요건 미확인.** 국내에서 소비자에게 유료 콘텐츠를 판매하면 통신판매업
  신고와 환불 규정 고지가 따라온다. 실제로 돈을 받기 시작하기 전에 확인이
  필요하다 — 코드로 해결되는 문제가 아니라 여기 적어둔다.
- **입금 자동대사 없음.** 관리자가 통장을 눈으로 보고 승인한다. 건수가 늘면
  오픈뱅킹 API로 자동 대조가 필요해진다.
