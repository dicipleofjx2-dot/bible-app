## 성경 방탈출

성경의 중요한 **사건·장면 하나가 곧 방 하나**다. 플레이어는 그 장면 안에
갇혀 있고, 그 사건에 대한 문제를 풀어 자물쇠를 하나씩 열고 마지막 문으로
나온다.

### 왜 이 종목이 대결의 주력인가

다른 종목은 점수 비교라 **동점이 자주 난다**(10문제 중 9개 맞히기는 흔하다).
방탈출은 **탈출에 걸린 시간**이 초 단위로 갈리므로 비동기 1:1에서 무승부가
거의 나지 않는다. 실시간 접속 없이도 승부가 선명하다.

### 방의 구조

```
방 하나 = 자물쇠 3개 + 최종 문 1개
```

- 자물쇠는 **순서대로** 열린다. 하나를 못 열면 다음이 안 보인다 — 방탈출의 긴장은
  "다음이 뭔지 모르는 것"에서 온다.
- 제한 시간(기본 5분)이 흐른다. 남은 시간이 곧 점수다.
- 자물쇠마다 힌트 1개. 쓰면 **시간 30초 차감** — 공짜가 아니어야 고민이 생긴다.
- 틀리면 **10초 차감**. 찍기를 막되 탈락시키지는 않는다.

### 자물쇠 네 종류

| 종류 | 화면 | 예 |
|---|---|---|
| `number` | 숫자 키패드 | "비가 며칠 밤낮 내렸는가" → `40` |
| `word` | 글자 입력 | "비둘기가 물고 온 잎사귀" → `감람나무` |
| `choice` | 객관식 | "처음 내보낸 새는" |
| `order` | 순서 배열 | 홍해 사건 6장면을 순서대로 |

### 콘텐츠를 코드에 두는 이유 (통독도우미와 다르다)

통독 해설·퀴즈는 DB(`reading_helper_chapter_content`)에 있다. 매일 새 분량이
생겨서다. 방탈출은 다르다:

- 방 개수가 **유한하고 매일 늘지 않는다** (사건은 정해져 있다)
- 자물쇠·힌트·정답이 얽힌 **중첩 구조**라 타입 검사를 받는 편이 훨씬 안전하다.
  jsonb에 넣으면 오타 하나가 배포 뒤에야 드러난다.
- 앱이 Expo 웹으로 배포되어 재배포가 몇 분이다

→ `src/lib/arena/rooms.ts`. **기록만 DB에 저장한다.**

### 점수 — 두 번까지, 평균

한 방에 **두 번**까지 들어갈 수 있고 **두 판의 평균**이 그 방의 점수다.
못 나온 판은 0점으로 평균에 들어간다(빼 주면 "1차를 망치면 그냥 나가면 된다"가
된다). 세 번째부터는 정책이 막는다 — 화면만 막으면 개발자 도구로 우회할 수 있다.

⚠️ 이 셈법을 **네 곳이 함께 본다**: `db.ts`의 `summarize` · 0060 의 두 순위 함수 ·
방 목록 화면 · 대전 홈의 설명글. 한 곳만 고치면 "내 점수는 이건데 순위표엔 저것"이
된다.

### 지금 있는 방 (14개)

난이도 순으로 보인다(쉬움 4 · 보통 5 · 어려움 5). 처음 들어온 사람이 첫 방에서
막히면 다시 안 오기 때문이다.

| 쉬움 | 보통 | 어려움 |
|---|---|---|
| 방주의 문이 닫혔다 (창 6~8) | 무너지지 않는 성벽 (수 2,6) | 홍해 앞, 막다른 길 (출 14) |
| 물고기 뱃속 (욘 1~2) | 사자굴의 밤 (단 6) | 한밤중의 옥문 (행 16) |
| 골짜기의 마흔 날 (삼상 17) | 왕의 감옥에 갇힌 종 (창 39~41) | 갈멜산의 젖은 제단 (왕상 18) |
| 고물에서 주무시는 분 (막 4) | 일곱 배 뜨거운 풀무 (단 3) | 돌이 막힌 무덤 (마 27~28) |
| | 광야의 마흔 날 (마 4) | 쇠사슬이 풀린 밤 (행 12) |

방 데이터는 `rooms.ts`(앞 6개) + `rooms2.ts`(뒤 8개)로 나뉘어 있다. 한 파일이
길어지면 방을 더할 때 남의 방을 잘못 건드리기 쉬워서다.

방을 더할 때는 `rooms.ts`의 주석에 적힌 **사실 확인 규칙**을 지킬 것 —
모든 정답에 장·절을 달아야 한다. 근거 없는 문제는 넣지 않는다.

## 둘이 겨루기

같은 방에 둘이 **동시에** 들어가 누가 먼저 나오는지 겨룬다.
`/arena/duel` → 대결 만들기(여섯 자리 번호) 또는 번호로 참가.

- 둘 다 「준비」를 누르면 서버가 시각을 찍고 **셋을 센 뒤** 함께 시작한다.
- 겨루는 동안 화면 위 띠에 상대가 몇 번째 자물쇠인지 보인다.
- 승부: 나온 사람 > 못 나온 사람 → 둘 다 나왔으면 시간 더 남긴 쪽 → 둘 다 못
  나왔으면 자물쇠 더 많이 연 쪽 → 그것도 같으면 무승부.
  (마지막 규칙이 있어야 질 것 같은 사람도 끝까지 한 자물쇠라도 더 연다.)
- 겨루기 판은 **개인 기록(두 판 평균)에 들어가지 않는다.**

### 왜 Realtime 을 안 쓰는가

이 앱은 Supabase Realtime 을 쓴 적이 없다. 새로 들이는 것이 안 되면 대결이
통째로 죽는다. 화면이 2초마다 물어보는 것으로 충분하다 — 상대 위치는 2초 늦게
보여도 되고 **승부는 서버에 저장된 기록으로 가린다.**

다만 그 2초 때문에 두 사람이 「시작됐다」를 아는 시점이 어긋난다. 초 단위로
갈리는 놀이에서 2초는 크다. 그래서 **서버가 찍은 `started_at` 에 3초를 더한
시각**을 둘이 함께 보고 세어 내려간다(`COUNTDOWN_MS`). EscapeRun 의 `startedAt`
프로퍼티가 그 값이다 — 늦게 안 쪽도 손해가 없다.

쓰기는 전부 `security definer` 함수로 한다. 표를 직접 UPDATE 하게 두면 상대
칸도 고칠 수 있고, 이건 상금이 걸린 대결이다.

승패 판정은 `node scripts/check-duel-judge.mjs` 로 11가지 경우를 잰다.

### 배포할 때 — `vercel.json` 에도 라우트를 더할 것

이 앱의 `vercel.json` 은 **동적 라우트마다 rewrite 한 줄**을 손으로 적어 둔다.
`[roomId].tsx` 같은 화면을 새로 만들면 거기에도 더해야 한다.

```json
{ "source": "/arena/escape/:roomId", "destination": "/arena/escape/[roomId]" }
```

⚠️ **빠뜨려도 로컬에서는 안 드러난다.** 로컬 검증에 쓴 `serve -s` 는 모든
경로를 index.html 로 떨어뜨려 클라이언트 라우터가 처리하지만, Vercel 은
rewrite 가 없으면 그냥 404 를 낸다. 배포 직전에 이 파일을 열어 보고서야
알았다.

배포는 `git push origin main` 으로 한다. `vercel --prod` 는 작업 디렉터리
전체를 올려서 **다른 세션의 미커밋 파일까지 딸려 간다** — 이 리포는 동시
세션이 함께 쓴다.

### 이때 잡은 결함 세 가지 (되풀이하지 말 것)

0. **다른 탭으로 옮기면 시계가 섰다.** `setInterval` 로 1초씩 빼고 있었는데
   브라우저가 안 보이는 탭의 타이머를 멈춘다(검증 중 1:43 에 멈춘 채 몇 분이
   지났다). 휴대폰에서 앱을 내려도 같다. **상금이 걸린 대회에서 「탭을 바꾸면
   시간이 안 간다」는 반드시 발각되고 악용된다.** 지금은 마감 시각(`Date.now()
   + 남은시간`)을 잡아 두고 거기서 거꾸로 잰다 → `deadlineRef`. 되돌리지 말 것.

1. **연타하면 앞 입력이 씹혔다.** 키를 누르는 자리에서 `digits + k` 로 다음 값을
   만들어 판정까지 했더니, 아직 다시 그려지지 않은 옛 `digits` 를 봐서 `300` 을
   누르면 `0` 만 남았다. **시간이 곧 점수인 게임이라 사람들은 최대한 빨리
   누른다** — 연타가 예외가 아니라 기본 동작이다. 지금은 누를 때 덧붙이기만
   하고(`setDigits(d => ...)`) 판정은 효과가 한다. 순서 자물쇠도 같다.
2. **문제 글에 마크다운을 쓰면 별표가 그대로 보인다.** 화면이 글자로 그리기
   때문. `**처음**` 이 화면에 별표째 나왔다. 검사 스크립트가 이제 막는다.

## 대회 (토너먼트)

`/arena/tournament` · 관리자는 `/arena/tournament/admin`

### 흐름

1. **관리자가 대회를 연다** — 이름, 예선 기간, 본선 인원(4·8·16·32)
2. **예선** — 그 기간에 친 방탈출 기록으로 점수를 낸다. 대회용 셈을 따로 만들지
   않는다: `arena_escape_scores(from, to)` 하나를 상시 순위표도 함께 쓴다.
3. **관리자가 예선을 마감**하면 상위 N명이 진출하고 대진표가 짜인다
4. **본선** — 짝지어진 둘이 **같은 방**을 각자 편할 때 한 번씩 풀고 점수를 견준다
5. **관리자가 라운드를 마감**하면 다음 라운드 대진이 생긴다
6. 결승까지 끝나면 👑 성경 왕중왕

### 시드 배정 — 되돌릴 수 없으니 미리 재 볼 것

1위와 꼴찌가 붙고, **1위와 2위는 결승에서야 만나야 한다.** 그냥 1-2, 3-4 로
짝지으면 상위 둘이 16강에서 만난다. `[1]` 에서 시작해 매번 뒤집어 붙이는
방식을 쓴다:

```
[1] → [1,2] → [1,4,2,3] → [1,8,4,5,2,7,3,6] → …
```

```bash
node scripts/check-bracket-seeding.mjs
```

4·8·16·32 명 모두에 대해 ① 시드가 빠지거나 겹치지 않는지 ② 첫 라운드 짝의 합이
`인원+1` 인지 ③ 상위 시드가 다 이기면 1위가 우승하는지 ④ **결승이 1 vs 2** 인지
⑤ 준결승에 상위 넷이 오는지를 잰다. 대회는 한 번 열면 되돌릴 수 없으니 대진
로직을 건드렸으면 반드시 돌릴 것.

### 승패를 가리는 순서

`arena_tournament_play` 가 서버에서 정한다(화면에서 가리면 다투게 된다):

**점수(남은 초) → 나왔는가 → 힌트 적게 쓴 쪽 → 먼저 친 쪽**

마감까지 안 치면 부전패. **둘 다 안 쳤으면 예선 성적이 좋은 쪽**이 올라간다 —
무승부로 두면 대회가 멈춘다.

### 대회 경기는 개인 기록과 별개다

본선 경기는 `arena_tournament_matches` 에 남고 `arena_escape_records` 에는 안
