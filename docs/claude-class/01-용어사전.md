# 개발 용어 사전 — 쉬운 말 풀이

클로드와 이야기할 때 나오는 말들이다. **외우지 말고, 들었을 때 알아듣는
것**이 목표다. 각 항목은 〈뜻 → 비유 → 이럴 때 쓴다〉 순서다.

---

## 1. 프로그램과 앱

### 프로그램 (Program)
컴퓨터에게 시킬 일을 글로 적어 둔 것. 모든 것의 출발점이다.

### 코드 (Code)
그 글의 한 줄 한 줄. "코드를 짠다"는 말은 "그 글을 쓴다"는 뜻이다.

### 앱 (App, 애플리케이션)
사람이 직접 쓰는 프로그램. 데이빗바이블이 앱이다.

### 웹 (Web)
주소창에 주소를 치면 열리는 앱. **설치가 필요 없고, 고치면 바로 반영된다.**

### 네이티브 앱 (Native App)
폰에 설치해서 쓰는 앱. 안드로이드는 APK, 아이폰은 앱스토어를 거친다.
**고치면 다시 설치해야 반영된다.** 웹과 가장 큰 차이가 이것이다.

> 한 벌의 코드로 웹과 네이티브를 함께 만드는 도구가 있다. 데이빗바이블이
> 그렇게 만들어졌다.

---

## 2. 앱의 구조 — 식당으로 보기

### 프론트엔드 (Frontend)
**식당의 홀.** 손님이 보는 곳. 화면, 글씨, 버튼, 색깔 — 눈에 보이는 전부.

### 백엔드 (Backend)
**주방.** 안 보이는 곳에서 계산하고 판단하고 규칙을 지킨다.

### 데이터베이스 (Database, DB)
**창고.** 이름, 글, 기도제목처럼 저장해 둔 정보가 쌓이는 곳.

### 서버 (Server)
**식당 건물.** 24시간 켜져 있는, 어딘가에 있는 컴퓨터.

### 클라이언트 (Client)
**손님 쪽.** 내 폰, 내 브라우저를 말한다.

> **이것만 알아도 절반은 전달된다** — "글씨 색을 바꿔 주세요"는 홀 일,
> "저장이 안 돼요"는 주방이나 창고 일이다.

---

## 3. 파일과 저장소 — 서류 캐비닛으로 보기

### 파일 (File)
코드를 담은 문서 하나. **종이 한 장.**

### 폴더 (Folder, 디렉터리)
파일을 모아 둔 칸. **서류함 한 칸.**

### 저장소 (Repository, 레포)
프로젝트 전체가 담긴 곳. **캐비닛 한 채.**

### 경로 (Path)
파일이 어디 있는지 적은 주소. `src/app/read.tsx` 처럼 생겼다.
**슬래시(`/`)는 "그 안의"라고 읽으면 된다** — src 안의 app 안의 read 종이.

### 확장자
파일 이름 끝의 `.tsx`, `.md`, `.json` 같은 꼬리표. 종류를 표시한다.

---

## 4. 깃 — 무한 되돌리기 장치

### 깃 (Git)
고친 내용을 전부 시간순으로 남겨 두는 장치. **게임의 세이브 포인트**이자
자동으로 찍히는 "다른 이름으로 저장"이다.

### 깃허브 (GitHub)
그 기록을 인터넷에 올려 두고 여럿이 함께 보는 곳.

### 커밋 (Commit)
"여기까지 저장" 하고 도장을 찍는 일. 왜 고쳤는지 한 줄을 같이 적는다.
**처음엔 이것 하나만 알면 된다.**

### 브랜치 (Branch)
원본은 그대로 두고 옆길을 내서 실험하는 것. 망쳐도 원본은 무사하다.

### 푸시 (Push)
내 컴퓨터에 쌓인 것을 인터넷(깃허브)으로 올려 보내는 일.

### 풀 (Pull)
인터넷에 있는 것을 내 컴퓨터로 내려받는 일.

### PR (Pull Request, 풀 리퀘스트)
"제가 옆길에서 한 작업을 원본에 합쳐 주세요" 하고 내는 요청서.

### 머지 (Merge)
그 요청을 받아들여 실제로 합치는 일.

### 충돌 (Conflict)
두 사람이 같은 줄을 서로 다르게 고쳐서 컴퓨터가 "어느 쪽이 맞나요?" 하고
묻는 상황. 사람이 골라 줘야 한다.

## 5. 버그와 에러

### 버그 (Bug)
만든 사람 뜻과 다르게 동작하는 것.

### 에러 (Error)
"못 하겠다"고 컴퓨터가 내놓는 메시지. 대개 빨간 글씨다.
**혼내는 말이 아니라 안내문이다.**

### 로그 (Log)
프로그램이 남긴 일기. 원인은 대개 여기 적혀 있다.

### 디버깅 (Debugging)
버그를 찾아 고치는 일 전체.

### 재현 (Reproduce)
같은 방법으로 버그를 다시 일으켜 보는 것. 고치기의 첫걸음이다.

> **오늘 가져갈 딱 한 가지** — 빨간 글씨가 뜨면 **통째로 복사해서** 클로드에게
> 붙여넣는다. 요약하지 않는다. 그 안에 답이 있다.

---

## 6. 내보내기 — 만든 것을 사용자에게

### 로컬 (Local)
내 컴퓨터 안. 아직 나만 볼 수 있는 상태.

### 빌드 (Build)
사람이 쓴 코드를 기계가 읽을 모양으로 굽는 일. **반죽을 빵으로.**

### 배포 (Deploy)
구운 것을 실제 사용자에게 내보내는 일. **가게 문을 여는 순간.**

### 도메인 (Domain)
사람이 외우는 인터넷 주소 이름. **가게의 간판.**

### 운영 / 프로덕션 (Production)
진짜 사용자가 쓰고 있는 곳. 여기서 실수하면 모두가 본다.

### 스테이징 / 프리뷰 (Staging, Preview)
사용자에게 내보내기 전에 미리 보는 연습용 자리.

> **전체 흐름**: 고침 → 저장(커밋) → 올림(푸시) → 굽기(빌드) → 문 열기(배포)

## 7. 빌려 쓰기

### API
다른 프로그램에 부탁을 넣는 **창구.** 은행 창구를 생각하면 된다.
"카카오톡으로 보내기", "지도 보여 주기" 같은 기능은 대개 남의 API를
빌려서 만든다.

### 라이브러리 (Library)
남이 미리 만들어 둔 **부품 모음.** 직접 만들지 않아도 된다.

### 패키지 (Package)
그 부품을 담아 내려받는 **상자.** "설치한다(install)"고 말한다.

### 프레임워크 (Framework)
집의 **뼈대.** 그 위에 살을 붙여 앱을 짓는다.

### SDK
어떤 회사의 서비스를 쉽게 쓰라고 묶어 준 **도구 상자.**

### 의존성 (Dependency)
내 프로그램이 돌아가려면 꼭 있어야 하는 남의 부품들.

## 8. 보안 — 가장 중요한 항목

### 키 (API Key, 토큰)
남의 서비스를 쓸 때 내미는 **신분증.**
**남이 가져가면 그 사람이 내 이름으로 쓰고, 요금은 내가 낸다.**

### 환경변수 (.env)
키를 코드 바깥에 따로 보관하는 자리. 코드를 공개해도 키는 남지 않는다.

### 노출 (Leak)
키가 남에게 새어 나간 상태. **되돌릴 방법은 키를 버리고 새로 받는 것뿐이다.**

### 절대 하지 않을 것
- 키를 코드에 직접 적기
- 화면 캡처나 영상에 키가 보이게 하기
- 채팅·메일에 키를 붙여넣기
- 키가 든 파일을 깃에 올리기

> 클로드에게 이렇게 말하면 된다 — **"이 키는 환경변수로 빼 주세요."**

## 9. 클로드가 자주 쓰는 말

### 테스트 (Test)
제대로 도는지 자동으로 확인하는 코드. **사람 대신 검사해 주는 검사원.**

### 타입 (Type)
"이 칸엔 숫자만" 같은 약속. 틀린 값을 미리 잡아 준다.
"타입 검사를 통과했다"는 **기본 문법 실수가 없다**는 뜻이지, 완성됐다는
뜻이 아니다. **화면이 원하는 대로인지는 사람이 봐야 한다.**

### 리팩터링 (Refactoring)
동작은 그대로 두고 코드만 정리하는 일. **방 가구 재배치.**

### 마이그레이션 (Migration)
저장 창고(데이터베이스)의 구조를 바꾸는 일. **선반을 새로 짜는 공사.**

### 롤백 (Rollback)
바로 전 상태로 되돌리는 일. **비상구.**

### 린트 (Lint)
코드 맞춤법 검사기.

### 캐시 (Cache)
한 번 가져온 것을 잠시 쌓아 두고 다시 쓰는 것. 빨라지는 대신,
**고쳤는데 화면이 그대로일 때 범인인 경우가 많다.**

### 리팩/핫리로드 (Hot Reload)
고치면 새로고침 없이 화면에 바로 반영되는 기능.

## 10. 파일 이름에서 자주 보는 것들

| 이름 | 무엇인가 |
| --- | --- |
| `README.md` | 이 프로젝트가 무엇인지 적은 안내문 |
| `package.json` | 이 프로젝트가 쓰는 부품 목록 |
| `.env` | 키를 넣어 두는 곳 (**절대 공유 금지**) |
| `.gitignore` | 깃에 올리지 말 것들의 목록 |
| `CLAUDE.md` | 클로드에게 주는 이 프로젝트의 규칙 |
