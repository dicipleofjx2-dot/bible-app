# 3강 — 토큰과 효율

## 왜 이걸 배우나

오래 쓰다 보면 세 가지가 생긴다.

- **느려진다** — 답이 나오기까지 점점 오래 걸린다
- **흐려진다** — 아까 한 말을 놓치고 엉뚱한 답을 한다
- **빨리 닳는다** — 쓸 수 있는 양이 금방 줄어든다

셋 다 **같은 원인**에서 온다.

> **클로드는 답할 때마다 지금까지의 대화를 처음부터 다시 읽는다.**

회의에 늦게 들어온 사람에게 매번 회의록 전체를 읽어 주는 것과 같다.

---

## 토큰 — 글을 세는 단위

클로드가 글을 읽고 쓸 때 세는 **낱개 단위**다. 한글은 대략 한 글자가 한두
토큰쯤 된다. 내가 쓴 말, 클로드가 쓴 답, 읽은 파일, 붙여넣은 에러 —
**오간 모든 글**이 토큰이다.

그래서 대화가 길수록 매 답변이 더 무거워진다. 스무 번째 답은 첫 답보다
훨씬 많이 읽고 나온 것이다.

---

## 책상에는 넓이가 있다

2강의 "한 대화 = 한 책상" 비유를 이어 간다.

| | 무슨 일이 일어나나 |
| --- | --- |
| **처음** | 서류 몇 장. 한눈에 다 보이고 답이 빠르다. |
| **한참 뒤** | 찾는 데 시간이 걸린다. 밑에 깔린 것은 잘 안 보인다. |
| **꽉 차면** | 오래된 것을 요약해 접어 둔다. 세부는 사라진다. |
| **그래서** | 치울 줄 알아야 한다. |

이 책상 넓이를 **컨텍스트**라고 부른다. 낱말은 몰라도 된다 —
**"한 번에 들고 있을 수 있는 분량"**이면 충분하다.

### 세 증상, 이제 설명된다

| 증상 | 왜 그런가 |
| --- | --- |
| 느려진다 | 매번 더 많은 글을 다시 읽어야 하니까 |
| 흐려진다 | 책상에 서류가 쌓여 아까 적어 둔 지시가 묻히니까 |
| 빨리 닳는다 | 읽는 양이 곧 쓰는 양이니까 |

효율은 요령이 아니라 **책상을 정리하는 습관**이다.

---

## 아끼는 일곱 습관

1. 작업 하나가 끝나면 **대화를 정리한다**
2. "전부 읽어 봐" 대신 **볼 곳을 가리킨다**
3. 긴 기록은 **관련된 부분만** 준다
4. 긴 결과는 화면 대신 **파일로** 받는다
5. 되풀이하는 지시는 **규칙이나 스킬로** 옮긴다
6. 찾는 일은 맡기고 **요약만** 받는다
7. **계획을 먼저** 본다 — 헛일이 가장 비싸다

> **예외**: 에러 메시지는 **통째로** 준다. 1강에서 배운 그대로다.
> 아끼는 것과 잘라 내는 것은 다르다 — 에러는 그 자체가 답이라 자르면 손해다.

## 이렇게 바꿔 보세요

| 무거운 방식 | 가벼운 방식 |
| --- | --- |
| "프로젝트 전체를 다 읽고 파악해 주세요" | "읽기 화면 하나만 보고 설명해 주세요." |
| 하루 종일 대화 하나로 버티기 | 기능 하나 끝날 때마다 정리하고 새로 시작 |
| 매번 "쉬운 말로 설명해 주세요" | 프로젝트 규칙에 **한 번** 적어 두기 |
| 긴 결과를 화면에 그대로 다 뽑기 | "그 내용을 파일로 만들어 주세요." |
| 매번 같은 순서를 처음부터 설명 | 스킬로 접어 두고 이름만 부르기 |

> 오른쪽이 **결과가 더 좋기까지** 하다. 좁게 물을수록 정확한 답이 온다.
