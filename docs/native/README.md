# 진짜 앱 — 안드로이드·아이폰으로 깔아 쓰기

데이빗바이블은 원래 웹 주소(davidbible.dgaiworks.com)로 쓰는 앱이었다. 웹으로는
할 수 없는 일이 생겨서 **휴대폰에 깔리는 앱**도 함께 낸다. 처음 그 일이 만보기였다
— 브라우저는 걸음 수를 읽을 길이 아예 없다.

같은 코드 한 벌로 셋을 만든다. 웹은 Vercel 로, 앱은 EAS(Expo 서버)로 빌드한다.

## 한 번 보고 아는 것들

| | 웹 | 안드로이드 앱 | 아이폰 앱 |
|---|---|---|---|
| 내는 곳 | Vercel | EAS → APK 파일 | EAS → App Store |
| 드는 돈 | 없음 | 없음(파일로 나눠 줄 때) | 애플 개발자 등록 연 $99 |
| 걸음 수 | 못 셈 | 앱 켠 동안 셈 | 하루 종일 셈 |

## 앱 새로 만들기

```bash
npx eas-cli build --platform android --profile preview
```

`preview` 는 **APK** 를 만든다. 주소를 열거나 QR 을 찍으면 바로 깔린다 —
플레이스토어를 거치지 않는다. 교인들에게 링크를 보내면 끝이다.

(스토어에 올릴 때는 `--profile production` 으로 AAB 를 만든다. 구글 플레이 개발자
등록 1회 $25 가 따로 든다.)

빌드가 끝나면 주소가 나온다. `npx eas-cli build:list --platform android --limit 1`
로 다시 찾을 수 있다.

### 열쇠(환경 변수)는 어디 있나

`.env` 는 깃에 올리지 않으므로 **EAS 서버에 따로 넣어 둔다.** 빌드할 때 거기서
가져온다. 새 열쇠가 생기면 `.env` 에만 넣지 말고 여기도 넣어야 한다.

```bash
npx eas-cli env:list --environment preview
npx eas-cli env:set --name 이름 --value 값 --environment preview --environment production
```

`eas.json` 의 빌드 프로필마다 `environment` 를 적어 두었다. 이것이 없으면 빌드가
다른 환경의 값을 집어 와서, **수파베이스 주소가 빈 채로** 앱이 나간다.

### 아이폰

아직 한 번도 안 만들었다. 만들려면 애플 개발자 등록(연 $99)과 애플 계정이
필요하다. 등록 뒤에는 `--platform ios` 한 줄이면 EAS 가 인증서까지 알아서 만든다.

## 만보기가 플랫폼마다 다른 까닭

`src/lib/pedometer.ts` 에 적어 두었다. 요약하면:

- **아이폰** — iOS 가 늘 걸음을 세고 7일치를 갖고 있다. 앱이 꺼져 있어도 「오늘
  몇 걸음」을 통째로 물어본다. 가장 정확하다.
- **안드로이드** — expo-sensors 로는 **앱을 켠 동안** 걸은 것만 센다. 하루치를
  받으려면 Health Connect(삼성헬스 등이 쌓아 둔 기록)를 읽어야 하는데, 그건
  모듈을 하나 더 붙여야 하는 길이라 아직 안 했다. 다음 걸음으로 둔다.
- **웹** — 셀 수 없다. 화면에 그렇게 적어 두고 손으로 적는 길만 둔다.

걸음 수는 `reading_helper_day_records.steps`(0095)에 하루 한 줄로 쌓는다.
**작은 수로 덮지 않는다** — 두 방식이 같은 칸에 들어오기 때문에 그냥 덮으면
하루 치가 거꾸로 줄어든다.

## 앱을 고쳤을 때

- 화면·글만 고쳤으면 웹만 다시 내면 된다. 앱은 그대로 둬도 된다.
- **새 네이티브 모듈을 붙였으면**(expo-sensors 처럼) 앱을 다시 만들어야 한다.
  깔려 있는 앱은 그 기능을 모른다.
- `app.json` 의 `android.versionCode` 는 스토어에 올릴 때만 올리면 된다. APK 로
  나눠 줄 때는 신경 쓰지 않아도 깔린다.
