# 수능영어 코치ON — 만든 것과 안 만든 것

기획서(`수능영어 AI 코칭 앱 기획서`)의 **1단계 MVP 중 학생용 전부**를 데이빗바이블
안의 한 영역(`/english`)으로 붙였다. 성장 탭 → 「📘 수능영어 코치ON」이 입구다.

## 왜 이 앱 안에 넣었나

별도 앱을 새로 세우면 계정·테마·라우팅·배포를 처음부터 다시 만들어야 한다.
이 영역은 **다른 화면과 아무것도 공유하지 않는다** — 표도 따로, 라우트도 한
폴더 안에, 성경 데이터도 안 쓴다. 나중에 떼어 내 독립 앱으로 옮길 때
`src/lib/english/`, `src/db/english.ts`, `src/features/english/`,
`src/app/english/` 네 덩어리만 들고 가면 된다.

## 설계에서 물러서면 안 되는 것들

1. **문항 번호가 아니라 학습 유형으로 분류한다** (기획서 §3 머리말). 회차마다
   번호가 달라지므로 번호를 키로 쓰면 데이터가 바로 썩는다.
2. **풀이 기록은 정답 하나가 아니다.** 선택한 답, 근거로 짚은 문장, 풀이시간,
   답을 바꾼 횟수, 확신도를 함께 남긴다(§5.4). 화면마다 풀이 UI를 따로 만들면
   그중 하나가 빠지고, 그러면 §6.1의 「찍어서 맞힌 문제」가 복습노트에 안 담긴다.
   그래서 진단·훈련·복습·실전이 **`QuizRunner` 하나**를 쓴다.
3. **오답 원인은 추측하지 않는다.** 선택지마다 「이걸 고른 학생은 무엇에 걸린
   것인가」(`Choice.cause`)를 문항 데이터에 적어 두었고, 추정은 그것을 읽는 것이
   1순위다. 신호(시간·확신도·근거 위치)로 넘어가는 것은 표시가 없을 때뿐이다.
4. **AI 추정과 학생 자기진단을 둘 다 남긴다**(§6.2). 다르면 그대로 둔다 —
   나중에 교사가 볼 자리다. 집계할 때는 학생이 고른 쪽을 센다.
5. **등급은 단정하지 않는다**(§8.3). 표본이 30문항 미만이면 ±1등급 구간으로 낸다.
6. **복습 실패는 0단계로 되돌린다**(§6.4). 한 칸만 물러나면 같은 자리를 오래 맴돈다.
7. **변형 문제를 풀면 원본의 단계가 오른다.** `recordAttempt(..., { advanceReviewFor })`.
   이게 없으면 3일째 변형 문제를 맞혀도 원래 틀린 문항이 영원히 0단계에 남는다.

## 문항 데이터와 저작권

지금 실린 30문항은 **전부 자체 제작**이다(`source.status === 'original'`).
기획서 §4.4대로, 공개되어 있다는 이유만으로 기출 원문을 앱에 담지 않는다.
담게 되면 `status`를 `'licensed'`로 바꾸고 `reviewedBy`/`reviewedAt`을 채운다.
이용 허가가 불명확한 것은 `'link-only'`로 두고 원문 링크만 준다.

문항을 늘릴 때는 `validateBank()`가 잡는 것들을 먼저 통과시킨다 — 정답이 선택지
안에 있는지, 오답마다 이유가 붙었는지, 근거 문장 인덱스가 지문 범위 안인지,
`variantOf`가 실재하는지. 문제은행 화면 맨 아래에 결과가 그대로 뜬다.

## MVP 목표 대비 (기획서 §18)

| 목표 | 지금 |
|---|---|
| 대표 유형 12~15개 | **15개** ✔ |
| 유형별 검수 문항 30개 이상 | 30문항이지만 **유형당 2개** — 총량은 맞고 유형별은 아직 부족 |
| 핵심 어휘·구문 태그 | 문항마다 어휘 3개·구문 1개 ✔ |
| 대표 기출 해설 세트 | 6단계 해설 전 문항 ✔ (기출이 아니라 자체 문항) |
| 진단평가 2세트 | **2세트** ✔ |
| 실전 미니 모의고사 5세트 | 6문항 × 5세트 ✔ |
| 복습용 변형 문항 풀 | 유형마다 1:1 변형 쌍 ✔ |

## 아직 안 한 것

- **교사용 코칭 센터(§9)** — 반·과제·학습지·코멘트. 이건 서버 표와 역할이
  필요한데, (가) 학생-교사를 무엇으로 잇는가(교회 초대코드 방식을 쓸지 학원
  좌석제로 갈지), (나) 이 Supabase 프로젝트를 같이 쓸지가 정해져야 스키마를
  쓸 수 있다. 정해지면 마이그레이션 한 장 + 화면 두 장이다.
- **듣기 영역(§3.1)** — 음원 관리와 재생 복구가 붙는 2단계 작업.
- **학부모 화면(§10)**, 결제·구독(§20).
- 기록이 **기기 안에만** 있다(`user.db`). 폰을 바꾸면 사라진다. 서버 동기화는
  교사센터와 같이 붙이는 것이 맞다 — 그때 `src/db/english.ts`의 함수 모양만
  유지하면 화면은 손대지 않아도 된다.

## 확인한 것 (2026-09-02)

- `tsc --noEmit` 통과 (기존 `@/global.css` 경고 1건만 남음, 이 작업과 무관).
- `expo export --platform web` 성공 — `/english` 아래 9개 라우트가 모두 프리렌더된다.
- 실제 브라우저(Chromium)에서 왕복 확인, **콘솔 오류 0건**:
  진단 15문항 완주 → 결과(영역별·약한 유형·원인·4주 처방)까지,
  학습 모드에서 오답 → 「왜 이 답을 골랐나」 → 6단계 해설 → 자기진단 → 복습노트 적재,
  복습노트에서 **변형 문제를 맞히자 원본 문항이 당일 → 1일 후 단계로 올라가는 것**.
- `npx expo lint`는 이 컨테이너에 eslint가 없어 못 돌렸다.
