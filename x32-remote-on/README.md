# X32 예배원격ON

안드로이드폰에서 Behringer X32 를 예배용으로 원터치 제어하는 앱. 기획서 1차(MVP) + §15 새부대교회 기본 화면.

> **이 폴더는 데이빗바이블과 무관한 독립 앱이다.** GitHub 앱에 새 리포 생성 권한이 없어(403)
> 임시로 bible-app 브랜치의 하위 폴더에 두었다. 새 리포를 만들면 이 폴더를 통째로 옮긴다:
> `git subtree split -P x32-remote-on -b x32-only && git push <새리포> x32-only:main`

## 실행

```
npm install
npm test          # 장비 없이 통신·안전 로직 16가지 검사 (가짜 X32 + 진짜 UDP)
npm run web       # 브라우저 — UDP 가 안 되므로 내장 시뮬레이터로만 동작
npm run emulator  # 이 컴퓨터를 udp/10023 가짜 X32 로. 폰 앱에서 이 PC IP 를 넣고 시뮬레이터를 끄면 붙는다
npm run build:android   # EAS 미리보기 APK. react-native-udp 가 네이티브라 Expo Go 로는 X32 에 못 붙는다
```

## 구조

| 파일 | 역할 |
|---|---|
| `src/osc/codec.ts` | OSC 인코딩/디코딩 (깨진 패킷은 null — 수신 루프가 죽지 않게) |
| `src/x32/targets.ts` | 채널·DCA·버스·메인 → OSC 주소 표. **주소는 여기 한 곳에만** |
| `src/x32/levels.ts` | 페이더 0~1 ↔ dB (X32 4구간 표, 0.75 = 0dB) |
| `src/x32/client.ts` | 연결·심장박동·상태·명령·페이드 엔진 |
| `src/x32/config.ts` | 교회별 채널 배치·한도. 복원 JSON 은 `sanitizeConfig` 로 거른다 |
| `src/x32/simMixer.ts` | 가짜 X32 (웹·검사·시연용) |
| `src/lib/actions.ts` | 버튼 → 명령. 잠금·관리자·최대값·진동을 **여기서 한 번에** 건다 |
| `src/app/(tabs)/` | 홈 · 빠른믹서 · 장면 · 설정 |

## 안전 설계 (§9, §11.3)

- **믹서가 진실이다.** 보낸 값으로 화면을 바꾸지 않고, X32 회신으로만 바꾼다.
- **끊기면 명령을 버린다.** 큐가 아예 없어서 재연결 때 몰아서 나가는 명령이 없다. 1초마다 `/info`, 3초 무응답이면 「연결 끊김 — 조작 잠김」 + 경고 진동, 진행 중 페이드 정지. 돌아오면 지켜보던 채널을 다시 읽는다.
- **페이드 중 누가 페이더를 잡으면**(믹서 앞·다른 폰) 즉시 멈추고, 이미 날아간 한 걸음이 그 값을 덮지 않게 잡은 값을 한 번 되돌려 준다(검사에서 실제로 걸린 경합).
- 긴급 음소거는 **지정 마이크만**, 2초 길게. 메인 LR 은 관리자 모드(2초 길게, 앱이 뒤로 가면 해제) + 최대값 한도.
- 장면 호출: 1초 길게 → 호출 직후 1.5초 조작 잠금 → 다시 읽기. 부르기 전 값을 찍어 두어 **되돌리기** 가능. 장면 저장·덮어쓰기는 앱에 없다.
- 앱이 뒤로 가면 조작 잠금. 화면 꺼짐 방지(keep-awake).
- 페이드 중에도 홈 버튼의 수·자리를 바꾸지 않는다 — 바뀌면 아래 버튼이 손가락 밑으로 밀려 온다.
- 외부 인터넷·서버 없음. 설정은 폰에만 저장.

## 아직 안 한 것 (기획서 2·3차)

전체 채널 스트립(EQ·Gate·Comp·Phantom), 개인 모니터, 매크로 편집기, OBS, 여러 X32 프로필, QR 배포, 작업 로그, 위젯, Wear OS, UDP 브로드캐스트 자동 검색(지금은 IP 직접 입력).

## 사람이 봐 줘야 하는 것

1. **실제 X32 에서** 주소·값 확인 — 특히 `/-action/goscene`, 장면 이름 `/-show/showfile/scene/NNN/name`, `/xremote` 가 보낸 쪽에 되돌려 보내지 않는지. 펌웨어별로 다르면 `targets.ts`·`client.ts` 만 고치면 된다.
2. `react-native-udp` 가 새 아키텍처(newArchEnabled)에서 빌드되는지 — 안 되면 `app.json` 에서 `newArchEnabled: false`.
3. 예배당 20~30m 거리 Wi-Fi 에서 지연·끊김 판정(3초)이 적당한지.
